@svta/cml-iso-bmff changelog ​

All notable changes to this project will be documented in this file.

The format is based on Keep a Changelog, and this project adheres to Semantic Versioning.

Unreleased ​

Added ​

  • IsoBoxReadView.readUint64 and IsoBoxWriteView.writeUint64 read and write a 64-bit unsigned integer as a bigint. readUint(8) and writeUint(value, 8) use a number, which loses precision above 2^53 - 1. A custom reader for a 64-bit field, such as baseMediaDecodeTime in a version 1 tfdt box, can now keep the exact value (#611).
  • readStco, readStsc, and readStsz are new readers for the stco, stsc, and stsz boxes (#619).
  • IsoBoxReadViewConfig has a new int64 option. The option takes a function that reads every 64-bit integer field of the built-in readers. With no option, the readers return the same values and the same types as before (#611).
  • readInt64AsBigInt is a new function for the int64 option. The built-in readers then return every 64-bit integer field as a bigint with the exact value. The result type of readIsoBoxes follows the option (#611).
  • createInt64OverflowReader is a new function for the int64 option. The built-in readers keep number fields. The function calls a callback with a RangeError when a 64-bit value is outside the safe integer range (#611).
  • IsoBoxReadView.readWideUint and IsoBoxReadView.readWideInt read a field of 4 or 8 bytes with the function of the int64 option. A custom reader that follows the option calls the two methods (#611).
  • defaultReaderConfig takes an optional argument with the int64 option. The readers of the returned configuration have the types of that option (#611).
  • IsoBoxWriteView.writeWideUint and IsoBoxWriteView.writeWideInt write a field of 4 or 8 bytes from a number or a bigint. The methods throw a RangeError for a bigint that does not fit the size (#611).
  • IsoInt64Reader is the type of a function for the int64 option. IsoInt64 is the type number | bigint of a 64-bit integer field (#611).
  • Each container box type in CONTAINERS now has a named reader, such as readMoov and readMoof. A container reader in the readers map is optional and does not change the result. readVttc reads the vttc box, and readVttC reads the vttC box (#297).
  • Each container box type in CONTAINERS now has a named writer, such as writeMoov and writeMoof. A container writer in the writers map is optional and does not change the written bytes. writeVttc writes the vttc box, and writeVttC writes the vttC box (#297).
  • TrackEncryptionBox has the new optional fields defaultConstantIvSize and defaultConstantIv. readTenc sets the fields for a tenc box with a constant IV (#648).
  • TrackEncryptionBox has the new optional field defaultIsProtected. readTenc sets the field to the protection state, which is the lowest byte of defaultIsEncrypted. writeTenc does not write the field (#648).
  • TrackEncryptionBox has the new optional fields defaultCryptByteBlock and defaultSkipByteBlock. readTenc sets the fields for a tenc box of version 1 or above. The value of defaultIsEncrypted does not change (#648).
  • writeTenc now writes defaultCryptByteBlock and defaultSkipByteBlock to a tenc box of version 1 or above. With no pattern field, the writer writes the pattern bits of defaultIsEncrypted. To change the pattern of a box from readTenc, change the pattern fields (#648).
  • EventMessageBoxUnrecognizedVersion is the new type of an emsg box of a version other than 0 or 1. The type has the fields of the versions 0 and 1 (#667).
  • EventMessageBoxUnrecognizedVersionNumber is the new type of the version field of EventMessageBoxUnrecognizedVersion. The values are 2 to 255 (#667).

Changed ​

  • The box types with 64-bit integer fields have a new type parameter for the type of those fields. The container types of those boxes, ParsedIsoBox, IsoBoxReadView, and the related types have the same parameter. The default is number, so existing references do not change (#611).
  • The built-in readers of boxes with no 64-bit integer field now take IsoBoxReadView<IsoInt64>. That type accepts a view with number fields or bigint fields. The readers from createAudioSampleEntryReader and createVisualSampleEntryReader take the same view (#611).
  • The readers of the boxes with 64-bit integer fields, such as readTfdt, are now generic functions. ReturnType<typeof readTfdt> now has number | bigint fields. Use the box type, such as TrackFragmentBaseMediaDecodeTimeBox, or ReturnType<typeof readTfdt<number>> (#611).
  • InstanceType<typeof IsoBoxReadView> and Parameters<typeof readTfdt>[0] are now IsoBoxReadView<IsoInt64>. Use the type IsoBoxReadView in place of those utility types (#611).
  • isIsoBoxType now narrows a box with bigint fields to the built-in box type with bigint fields. A box that can be null or undefined narrows in the same way (#611).
  • The writers of the boxes with 64-bit integer fields now take a box with number fields or bigint fields. writeIsoBox, writeIsoBoxes, and createIsoBoxReadableStream take the same boxes. A box that readIsoBoxes reads with readInt64AsBigInt writes back with the exact values (#611).
  • Parameters<typeof writeTfdt>[0] now has number | bigint fields. The other ten writers of boxes with 64-bit integer fields, writeIsoBox, and writeIsoBoxes have the same change. Use the box type, such as TrackFragmentBaseMediaDecodeTimeBox, or IsoBoxStreamable (#611).
  • With readInt64AsBigInt, a custom reader of the type (view: IsoBoxReadView) => ... is a compile error. Type the view as IsoBoxReadView<IsoInt64>, or make the reader generic and call readWideUint (#611).
  • Required<IsoBoxReadViewConfig> now has a required int64 key. A value of that type with no int64 function is a compile error. Use Required<Pick<IsoBoxReadViewConfig, 'readers'>> for a configuration with required readers (#611).
  • A subclass override of IsoBoxReadView.readUint or IsoBoxReadView.readInt no longer runs for a 64-bit integer field of a built-in reader. The constructor assigns the methods of the base class to readWideUint and readWideInt. To run the override, pass an int64 function that calls view.readUint and view.readInt (#611).
  • The reading guide has a section on a function that forwards the int64 option. The guide also states that JSON.stringify throws a TypeError for a bigint (#611).
  • UserDataBox, GroupsListBox, SubTrackBox, AdditionalMetadataContainerBox, and MetaBox now have the type parameter for the type of the 64-bit integer fields. The default is number, so existing references do not change (#646).
  • readMeta is now a generic function, so ReturnType<typeof readMeta> is MetaBox<number | bigint>. Use the type MetaBox in place of that utility type (#646).
  • writeMeta now takes a MetaBox with number fields or bigint fields (#646).
  • The type of a udta, grpl, strk, or meco child no longer has the view and size fields. Cast the child: (child as ParsedIsoBox).view (#646).
  • A udta, grpl, strk, or meco box no longer accepts a child of another type, such as a Uint8Array. Cast that child: bytes as unknown as IsoBox (#646).
  • writeIsoBox and writeIsoBoxes now throw No writer found for box type for a box that has no writer and no view. The rule applies to a box with a boxes field and a type outside CONTAINERS, such as a meta box that code builds. Add the writer for the type, such as writeMeta, to the writers map (#651).
  • EventMessageBox now includes EventMessageBoxUnrecognizedVersion. After a check of version === 0, the other branch is no longer EventMessageBoxV1. To narrow to EventMessageBoxV1, check version === 1 (#667).
  • The documentation of IsoBoxReadView.readTemplate now states that the method reads an unsigned fixed-point value.
  • The documentation of IsoBoxWriteView.writeTemplate and of the TEMPLATE field type now describes a fixed-point value. The writeTemplate documentation states the sizes 2 and 4 and the storage of a negative value.
  • The documentation of the matrix field of MovieHeaderBox and TrackHeaderBox now states the entry order and the identity matrix. The documentation also states the stored formats.
  • The documentation of the balance field of SoundMediaHeaderBox now states the values for full left, center, and full right.
  • The reading guide has a section on extending a built-in reader. The example decodes the ID3 frames of an emsg box.
  • isIsoBoxType accepts unknown as the box argument instead of any. The guard now also returns false for null and for values that are not objects.
  • writeIsoBox and writeIsoBoxes now return Uint8Array<ArrayBuffer>. The result passes to SourceBuffer.appendBuffer without a cast under TypeScript 6 and later. A box given as a view over a SharedArrayBuffer is copied, so the result is always backed by an ArrayBuffer. The type declarations now need TypeScript 5.7 or later.
  • The README now has a When to use section. The section names the tasks that the package covers and the entry point of each task.
  • The utilities guide examples now store the results of isContainer and isFullBox in container and fullBox. The examples no longer redeclare the imported names.
  • Every code example in the guides now typechecks. The writing examples pass each Uint8Array to appendBuffer directly, and the traverseIsoBoxes example reads the boxes first (#565).
  • The reading guide has a section on incomplete boxes, and the writing guide links to that section. The documentation of readIsoBoxes, IsoBoxReadView.readBox, and IsoBoxReadView.readBoxes now states where the read stops (#650).
  • The reading guide now states that a box with a size below the size of the box header is incomplete. The documentation of readIsoBoxes, IsoBoxReadView.readBox, and IsoBoxReadView.readBoxes states the same rule (#663).
  • The README and the homepage field of package.json now link to the package page on the website, cml.svta.org/packages/iso-bmff.
  • writeElng, writeIden, writeKind, writeLabl, writePayl, writeSttg, and writeVlab now encode each string one time. The written bytes of writeElng, writeKind, and writeLabl do not change (#632).
  • writePrsl now encodes each tag one time. The written bytes do not change.
  • The reading guide and the documentation of IsoBoxReadView.readBox now state that the header of a uuid box has 16 more bytes for the usertype field.
  • writeEmsg, writeHdlr, writeUrl, writeUrn, and writeSchm now need TextEncoder, as the other UTF-8 writers do. Earlier releases write these boxes with no TextEncoder (#643).
  • IsoBoxReadView now has one rule for the size limit of readData and readUtf8. The results of both methods do not change.
  • readIsoBoxes now calls IsoBoxReadView.readBoxes. The result does not change.
  • readTfra now computes the size of the 64-bit integer fields one time for each box.
  • writeTkhd now writes layer and alternateGroup as signed integers, as readTkhd reads them. The written bytes do not change.
  • The examples of readIsoBoxes, writeIsoBoxes, traverseIsoBoxes, and createIsoBoxReadableStream now use strictEqual and deepStrictEqual. The writeIsoBoxes example compares the written bytes with a Uint8Array of the file.
  • The README has a quick start with one read example and one write example. A new section lists the runtime APIs that some exports need.
  • The reading guide states that readIsoBoxes throws a RangeError for a complete box with a body shorter than its fields. The guide also states the rules for the size field, the input types, and shared byte fields.
  • The reading and writing guide examples find a tfdt box with findIsoBox. The earlier examples looked for the box at the top level, where a segment does not have it.
  • The bigint example of the reading guide keeps the fraction of the seconds. The guide also states that an all-ones duration reports an overflow to createInt64OverflowReader.
  • The writing guide states the exact keys of the writers map and the rule for flags and missing fields. The appendBuffer examples wait for the updateend event.
  • The utilities guide describes the configuration of traverseIsoBoxes and has a section on findIsoBox, filterIsoBoxes, and isIsoBoxType.
  • The documentation of readIsoBoxes, writeIsoBox, writeIsoBoxes, createIsoBoxReadableStream, and IsoBoxReadableStream now has @throws tags.
  • The summary of each reader and writer names the four-character type of its box. The summary of each box type uses one form and cites ISO/IEC 14496-12:2015 where that edition defines the box.
  • The documentation of the mvhd, tkhd, mdhd, mehd, elst, mfro, tfhd, and tfra fields states the units, the 1904 epoch, and the flags. Byte fields state that they are a view over the input.
  • 25 readers and writers and 7 other exports now link a test example. Each linked example declares its input, except the examples of IsoBoxWriteView.writeUint and writeIsoBoxes.
  • traverseIsoBoxes is faster. The largest gain is in breadth-first order over many sibling containers. The order of the boxes does not change (#706).
  • IsoBoxReadView.readBox now reads the four characters of the box type in one call. readIsoBoxes is about 3% faster (#706).
  • writeCtts and writeTrun now write the signed offset fields as signed integers, as readCtts and readTrun read them. The written bytes do not change.
  • isFullBox accepts unknown as the box argument instead of any. The guard now also returns false for null and for values that are not objects.
  • IsoBoxType is now declared as string. The type accepts the same values as before. The documentation states that TypeScript does not check the length of a box type.
  • readVtte and writeVtte now name their parameters _view and _box, and the documentation describes the parameters.
  • The documentation of readInt64AsBigInt and the reading guide now test for DataView.prototype.getBigUint64. A runtime can have BigInt and no getBigUint64 method. The documentation of readUint64, writeUint64, writeWideUint, and writeWideInt names the DataView method that each one needs.
  • The runtime requirements table of the README now lists the DataView methods that the bigint reads and writes need.
  • The description of the package now states that the package reads and writes boxes.
  • The UTF-8 string reads now call decodeUtf8 of @svta/cml-utils. A bundle with readIsoBoxes is about 200 bytes smaller after gzip. The results do not change. The package now needs @svta/cml-utils 1.8.0 or later.

Fixed ​

  • The published package includes NOTICE.md.
  • IsoBoxReadView.readUtf8(-1) now moves the view to the byte after the null byte of a string that has multi-byte characters. readKind, readLabl, and readPrsl now return the correct fields after such a string. Earlier releases return an empty value for a kind box with the schemeUri urn:é (#630).
  • IsoBoxReadView.readUtf8(-1) and IsoBoxReadView.readString(-1) now stop at the end of the view when the string has no null byte. Earlier releases move the view one byte past the end, and bytesRemaining is -1 (#635).
  • IsoBoxReadView.readUtf8() with no size now moves the view to the end of the view. Earlier releases return the string and do not move the view (#635).
  • IsoBoxReadView.readUtf8(size) with a positive size now reads size bytes. With a size that exceeds the bytes that remain, the method reads to the end of the view and stops there. Earlier releases read every byte up to the end of the view (#635).
  • IsoBoxReadView.readUtf8(0) now reads no bytes and returns an empty string. Earlier releases return the string up to the end of the view (#635).
  • IsoBoxReadView.readData(size) now stops at the end of the view when size exceeds the bytes that remain. Earlier releases return bytes that follow the view, or throw a RangeError when the read goes past the end of the buffer (#644).
  • IsoBoxReadView.readData(0) now reads no bytes and returns an empty array. Earlier releases return every byte up to the end of the view. If your code passes 0 or no size to read to the end of the view, pass -1 (#644).
  • IsoBoxReadView.readBoxes(0) now reads no boxes and returns an empty array. Earlier releases return every box of the view. If your code passes 0 to read every box, pass -1 or no length (#666).
  • readDref and readStsd now return no entries for an entry_count of 0. A write of the box then keeps the count of 0 and writes no entries. Earlier releases return the boxes after the count, so a write changes the count to the number of those boxes (#666).
  • The hdlr, url , urn , and schm readers and writers now use UTF-8 for the name, location, and schemeUri strings. Earlier releases return å, for a name of 日本 after writeHdlr and readHdlr (#631).
  • IsoBoxReaderReturn no longer adds the built-in type of a box whose reader the configuration replaces. The result of readIsoBoxes with a custom tfdt reader now narrows to the return type of that reader (#611).
  • IsoBoxReaderReturn now includes the return type of an optional reader and no longer includes undefined (#611).
  • writeSchm now writes the null terminator of an empty schemeUri when flag 0x000001 is set. The writer writes an empty string for a missing schemeUri (#628).
  • IsoBoxReadView.readInt(8) now returns the correct value for a signed 64-bit integer such as -1. readElst now returns the correct mediaTime for a version 1 elst box, where -1 marks an empty edit. Earlier releases return -4294967297 for -1.
  • writePrsl now writes every tag that the flags declare. The writer writes an empty string for an empty or missing preselectionTag or interleavingTag. Earlier releases omit an empty tag, and a read of the written box returns no child boxes (#624).
  • defaultReaderConfig() now includes readers for the stco, stsc, and stsz boxes. writeIsoBoxes with defaultWriterConfig() now writes the stco, stsc, and stsz boxes that readIsoBoxes reads with defaultReaderConfig(). Earlier releases throw a RangeError for stco and stsc, and write stsz without the sample sizes (#619).
  • writeUrl no longer writes the location string when flag 0x000001 is set, even when location is not empty. Earlier releases add a null byte, so the url box and the enclosing dref box are one byte too long (#623).
  • writeIden, writePayl, writeSttg, and writeVlab now write the string of the box with no null byte after the string. readIden, readPayl, readSttg, and readVlab still read the same string from a box that has the null byte. Earlier releases write a null byte after the string (#636).
  • IsoBoxReadView.readTemplate now reads the fraction of a fixed-point value, so the bytes 00 01 80 00 read as 1.5. Earlier releases return 8193 for these bytes. The built-in readers now return the correct fraction of rate, volume, matrix, width, height, horizresolution, vertresolution, and samplerate.
  • readMvhd now reads rate as a signed value. A rate of -1 now reads as -1. Earlier releases return 65535 for this rate.
  • readMvhd and readTkhd now read volume and matrix as signed values. A matrix entry of -1, as in a rotated video, now reads as -1. Earlier releases return 65535 for this entry.
  • readTkhd now reads layer and alternateGroup as signed values. A layer of -1 now reads as -1. Earlier releases return 65535 for this layer.
  • readMvhd and readTkhd now read the matrix entries u, v, and w (indexes 2, 5, and 8) as 2.30 values. The entry w of the identity matrix now reads as 1. If your code compares w with 16384, compare w with 1.
  • writeMvhd and writeTkhd now write the matrix entries u, v, and w as 2.30 values. If your code passes 16384 for w, pass 1. The value 16384 now writes 0.
  • readSmhd now reads balance as a signed 8.8 value. The balance for full right reads as 1, and the balance for full left reads as -1. Earlier releases return 256 for full right and 65280 for full left.
  • writeSmhd now writes balance as a signed 8.8 value. If your code passes 256 for full right, pass 1. The value 256 now writes 0.
  • readEmsg and writeEmsg now read and write schemeIdUri and value as UTF-8, as ISO/IEC 23009-1 defines the fields. Earlier releases use one byte for each character, so a character that is not ASCII gives wrong bytes or a wrong string. A string with only ASCII characters reads and writes the same bytes as before (#643).
  • readIsoBoxes no longer throws a RangeError when the data ends inside a box header. The function returns the boxes before that header. The function now reads a sample entry or a udta box with 4 zero bytes after the last child box (#650).
  • writeIsoBoxes omits the bytes that readIsoBoxes stops before. The written box is shorter than the source box by those bytes. If the moov box precedes the mdat box, the chunk offsets of the written file then address other bytes (#650).
  • IsoBoxReadView.readBox now throws an Error with the message Truncated box when the view ends inside a box header. Earlier releases throw a RangeError for that view (#650).
  • readIsoBoxes now stops before a box with a size below the size of the box header. The function returns the boxes before that box. Earlier releases return boxes with wrong types, omit the next box, or throw a RangeError (#663).
  • readIsoBoxes now returns for a box with a size of 1 and a largesize of 0. Earlier releases read that box again without end, and the memory use grows (#663).
  • IsoBoxReadView.readBox now throws an Error for a box with a size below the size of the box header. The message is Truncated box. Earlier releases return that box, and the next read starts inside the header of that box (#663).
  • readIsoBoxes now stops before a uuid box with a size below 24, or below 32 with a largesize field. The function returns the boxes before that box. Earlier releases throw a RangeError when that box is the last box of the data or of a container.
  • IsoBoxReadView.readBox now throws an Error with the message Truncated box for a uuid box with a size below 24. Earlier releases throw a RangeError, or return a usertype with bytes of the next box.
  • readPssh and writePssh now read and write 16 bytes for each key ID of a version 1 pssh box. The kid field has 16 numbers for each key ID. Earlier releases use one byte for each key ID, so readPssh returns a wrong dataSize and data or throws a RangeError (#649).
  • writeTenc now writes the constant IV of a tenc box that has defaultConstantIvSize or defaultConstantIv. A read and then a write of the box returns the source bytes. Earlier releases write 32 bytes and drop the constant IV (#648).
  • The children of the udta, grpl, strk, and meco boxes now have the type IsoBox. Earlier releases give each child the type any, so TypeScript checks no field of a child. Test child.type before you read a field of a child (#646).
  • After isContainer(box), each element of box.boxes now has a box type. A 64-bit integer field of a child has the type of the int64 option (#646).
  • writeIsoBox and writeIsoBoxes now write the source bytes of a parsed box with a boxes field and no writer. The rule applies to every type outside CONTAINERS, such as meta, prsl, and the sample entries. Earlier releases write only the header and the child boxes of such a box, so its other fields are lost (#651).
  • readEmsg now returns the source version for an emsg box of version 2 or above. messageData has all bytes after the full box fields, and the other fields are empty strings or 0. Earlier releases read the fields of version 0 and return version: 0 (#667).
  • writeEmsg now writes only the full box fields and messageData for a version other than 0 or 1. A read and then a write of such a box return the source bytes. Earlier releases write the fields of version 1 (#667).
  • IsoBoxWriteView.writeUint(value, 8) and the built-in writers now write all bits set for a number of 2^64 or more. Earlier releases write 0. A read and then a write with the default configs now keep a 64-bit field with all bits set, such as duration in mvhd (#653).
  • readSidx and writeSidx now read and write earliestPresentationTime and firstOffset as 64-bit fields for a sidx box of version 2 or above. Earlier releases use 32-bit fields for every version other than 1 (#670).
  • readPrft and writePrft now read and write mediaTime as a 64-bit field for a prft box of version 2 or above. Earlier releases use a 32-bit field for every version other than 1 (#670).
  • readCtts now returns entryCount and an empty entries list for a ctts box of version 2 or above. The syntax defines no entries for those versions. Earlier releases read the entries with the layout of version 0 (#670).
  • writeCtts now writes entryCount and no entries for a ctts box of version 2 or above. Earlier releases write every element of entries for every version (#670).
  • readTrun now reads sampleCompositionTimeOffset as a signed integer for a trun box of version 2 or above. Earlier releases read a signed integer only for version 1 (#678).
  • readIsoBoxes and IsoBoxReadView now read an ArrayBuffer from another realm, such as a node:vm context or an iframe. Earlier releases throw a TypeError for that ArrayBuffer.
  • IsoBoxReadableStream and createIsoBoxReadableStream now close the source iterator when the stream is canceled. The finally block of a generator source now runs. Earlier releases leave the iterator open.
