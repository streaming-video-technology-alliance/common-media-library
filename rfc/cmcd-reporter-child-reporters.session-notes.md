## Outstanding work, in order

1. **Prerequisite-fixes PR** (lands before the feature; file issues first, branch `issue/<n>-<slug>` per repo convention). Six verified bugs, all with reproductions from this session:
   - **Reserved keys merge-overridable**: `recordEvent('ps', { sid: 'INJECTED' })` emits the foreign sid; per-call `msd` bypasses the gate. Fix: stamp `sid`/`msd` after caller data and transforms in both modes (extend the #399 stamping step in `queueTargetEvent()` and the request path).
   - **`msd` validation**: guard is `if (data.msd && !isNaN(data.msd))` at `CmcdReporter.update()`; rejects `0`, accepts `Infinity`/negatives/fractions (`msd=12.5` and `msd=-500` reach the wire). Fix: finite, non-negative, `Math.round`ed. Test table: `0` accepted, `12.5` rounds to `13`, `Infinity`/`-1`/`NaN` rejected.
   - **`resetSession()` never clears `msd`/`msdSent`**: post-`sid`-change `msd` is silently never sent.
   - **`msd` gate consumed before the key filter**: with `msd` absent from `enabledKeys`, the report omits `msd` but `msdSent` flips to `true` (verified both modes; request path sets the flag before `prepareCmcdData()` filters; event path stamps at enqueue but filters at encode). Fix: consume the gate only when the prepared output retains `msd`. No observable single-reporter output change.
   - **HTTP 410 disposal outlives the session**: repro `s1 -> 410 -> update({ sid: 's2' }) -> new event` = one requester call total, target map empty; a delayed 410 resolved after the `sid` change also kills the new session's target. Spec: cease "for the remainder of the current session". Fix: restore disposed targets on session reset + session-epoch guard on async 410 handling.
   - **`update({ sid: undefined })` poisons the store** (explicit `undefined` merged in; reset guard skipped). Fixed for free by report-time `sid` stamping.
   - Plus the two land-first pin tests from the RFC's Testing section: 429/5xx re-queue path; `sn` reset on `sid` change with real assertions.
2. **Design pass for automatic starvation-counter tracking** (planned with the prerequisite PR). Agenda in Unresolved questions item 4. Artifact goes in `plans/` per AGENTS.md, suggested `plans/cmcd-session-counters/`.

## Key verified facts (do not re-derive)

- **Spec (CTA-5004-B)**: contains no duplicate-suppression clause for state events; state-change triggers are player-scoped; `bg` is defined over "all players in a session"; `msd` is "Integer milliseconds" and once per Session ID per active mode; 410 suppression is scoped to "the remainder of the current session"; no delivery-deadline language exists anywhere (deferred delivery twice endorsed); mixed v1 request mode with v2 event mode is recommended; per-target versions are live library behavior today; the only multi-player example (8.1.7) shows interleaved per-player lines under one `sid` disambiguated by `cid`/`nr`; the only `t` example (8.2.2) is a single stream "for an active player".
- **hls.js (master, verified in source)**: `interstitialAppendInPlace` transfers the media element and MediaSource/SourceBuffers to the child `Hls` instance; the primary's `CMCDController` detaches (media nulled, buffer queries `NaN`); `CMCDController.destroy()` unconditionally calls `reporter.stop(true)` per asset teardown, plus a reset path.
- **TypeScript (repo's 5.8.2, strict, no `exactOptionalPropertyTypes`)**: `never` locks reject literal, widened, and spread-built configs; `Omit` alone only guards literals; locks render as `undefined` in tooltips/errors (TSDoc carries the reason); a `Pick` including a factory returning the class is nominal across package copies; a recursively structural alias is not.
